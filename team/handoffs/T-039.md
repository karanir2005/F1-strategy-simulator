# T-039 frontend fixes from the QA sweep (frontend-engineer, 2026-10-23)

## Changed
- `lib/api.ts`: optional `race.race_start_utc` / `quali_start_utc` on RaceInfo; 60 s fetch timeout with its own error message.
- Countdown (`countdown.tsx`): with start times it counts to the real session start (qualifying first, then race; grid mode skips quali) and lists each session in the viewer's local time. Without them it shows whole days using the same local-calendar logic as the status line (no h/m/s, labelled "exact start time not available"). `weekendStatus` guards an empty/invalid date.
- `/strategy`: a track change clears optimizer and manual results/errors/loading and bumps an epoch ref, so late responses for a previous track are dropped. Results caption "track · laps · safety cars on/off". The "Is the backend running?" hint shows only for unreachable/timeout errors.
- `compare-results.tsx`: SC copy follows `safety_cars`; returned `assumptions` listed; noise wording now uses `NOISE_FLOOR_S` (5 s) like the optimizer.
- Manual plans must total the track's laps when a track is selected and not overriding (`getValidationError` new optional `requiredLaps`).
- Small: non-2026 track notes shown inline under the badge; "still loses most of the time" only when p_win < 0.5; Qualifying tab reads "Qualifying (pre-quali prediction)" once an actual grid exists; "+x.x s vs best" text under 640px in optimizer top plans; single-plan optimizer copy; `== null` guards in probability-table.

## Verified
`npx tsc --noEmit` and `npm run lint` clean; /predict and /strategy return 200 on the running dev server. NOT verified in a browser: countdown with real start times (backend fields not live yet), 360px layout, the request-guard race, and the long Qualifying tab label at 360px (parent wraps, but unchecked). No `npm run build` run, per instruction.
