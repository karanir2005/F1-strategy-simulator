**Delta presentation (code + harness):**
- Sign: positive means slower than the reference. `formatDelta(1.726)` gives "+1.73s", `-4.614` gives "-4.61s", and a leading "+" is added for >= 0. It matches the backend: a live run showed the 1-stop with `start_age` 15 at delta +1.48 and p10 -4.81 / p90 +8.08 versus the 2-stop reference.
- The reference row is identified by `r.name === results.reference_strategy`, not by position. Rows are sorted by mean on the client. The sort is stable, so the first-listed row wins ties, which agrees with the backend's tie rule, and the 🏆 goes on row 0. The reference shows a "reference" badge and the text "reference", with "--" in the range column.
- "constant" appears only when `|p90 - p10| < 0.005`:
  - 0.31/0.31 and 0.31/0.3149 give "constant +0.31s".
  - 0.31/0.32 gives the range "+0.31s to +0.32s".
  - -4.61/8.0 gives "-4.61s to +8.00s".
  - Live same-stop-count case: "A" delta 0.16/0.16/0.16 gives "constant +0.16s".
- Zero: 0 and -0 both give "+0.00s".

- A stale start age is not validated when "used set" is unticked (26 with `usedSet:false` passes), which is correct because it is never sent.
- Run is `disabled={loading || !!validationError}`, and `handleRun` also returns early on `validationError`. "Add strategy" is disabled at 20.

**422 rendering (`formatDetail`, via the real `runSimulation`, and with real backend bodies):**
- String detail → "Simulation request failed: plain string".
- List with `msg` and `loc` → "strategies > 0 > stints > 0 > start_age: Input should be less than or equal to 25". The leading "body" is stripped and "Value error, " is removed.
- The real unequal-totals 422 reads "strategies: all strategies must cover the same total race laps ... got {'A': 40, 'B': 30}".
- Real 422s for laps 101, n_sim 50001, 21 strategies, total 101 and `start_age: null` also render readably.
- Odd shapes are handled: a list item without `msg` is JSON-stringified, an object detail is JSON-stringified, and a missing or unparseable body gives "HTTP 422".

**F-1 (used-set independence): fixed.**
- Trace with the shipped `parseNum` and state shape: typing "" gives `{usedSet:true, startAge:""}`, then "1" gives `{usedSet:true, startAge:1}`, then "15" gives `{usedSet:true, startAge:15}`. The input is rendered on `stint.usedSet`, not on `startAge`, so it stays mounted at every step.
- The checkbox is bound to `stint.usedSet`. `setUsedSet` only changes `usedSet`, and re-ticking with an empty age restores 2.
- Payload: `start_age` is included only when `usedSet && startAge !== 1`. Unticking leaves the key out. The stored age is kept (see N-2).

**F-4 (cleared fields): fixed in logic.**
- `parseNum("")` gives `""`, and `"abc"` gives `""`. Every numeric state is typed `number | ""`. A cleared field blocks Run (sims, base lap time, pit loss, laps, used-set age).
- `handleRun` only casts after validation, so `""` never reaches the payload. The payload carries no NaN and no null `start_age`. A live `start_age: null` returns 422 `Input should be a valid integer`, so the omit-not-null behaviour is needed and is implemented.
- Mirror of T-007's `start_age` upper bound: present, input `max={25}` plus validation.

**Win-probability footnote:** accurate and now secondary. The column is last, the tooltip starts "Secondary", and the footnote says to read the gap first. Live check: the same-stop-count pair shows 0 / 1 win probability with a 0.16 s gap, and identical strategies give 1 / 0, which matches the footnote's "exactly 0% / 100% even when the gap is a fraction of a second". The paired-gap footnote is correct. It says negative p10 means the strategy beat the reference in at least 10% of simulations, which matches the T-007 note. The "about a second or less is inside model error" wording is frontend copy and is consistent with the replay errors of 27-150 s.
