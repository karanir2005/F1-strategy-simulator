## Findings
1. **MEDIUM-HIGH, silent wrong output on Saturday. Owner: data-scientist (or backend-engineer).**
   - **Where:** `predict_race.py::_entry_and_grid`, the qualifying branch. The `base` entry list comes from `P.entrants_for`, which returns the rows of the qualifying table. The code that places drivers "without a quali classification at the back" can therefore never run.
   - **Why it matters:** Jolpica's qualifying table omits drivers who set no time, yet they start the race. In cached 2026 data, R1 is missing VER, SAI and STR (VER started P20 and finished), and R14 is missing BEA and STR. Qualifying rows per round are 19/22/.../20/22.
   - **Effect:** if this happens at COTA, auto mode silently drops those cars from the field. A missing contender inflates everyone else's probabilities, and the sums are still 1/3/10, so nothing looks wrong. The `--grid-file` path is unaffected.
   - **Repro:** `test_t012_qa.py::test_drivers_missing_from_jolpica_quali_still_in_field` (currently xfail; it will pass once the field is 22).
   - **Fix:** take the entry list from the latest earlier round, or the schedule's entrants, union the qualifying rows, and put missing drivers at the back. Failing that, warn when the qualifying row count is not 22.
2. **LOW, `--grid-file` is not validated.**
   - Duplicate codes, duplicate or non-contiguous grid numbers and fewer than 22 rows are all accepted silently.
   - Only unknown codes stop the run. A grid file with a missing driver would also drop that car without warning.
   - Suggest an assertion on row count and the grid set.
3. **LOW, pre-quali entry list.** It is the previous round's entrants. A reserve driver or lineup change for round 18 is invisible in pre-quali mode (already noted in the handoff), and Friday's `--mode prequali` rerun changes nothing.
4. **LOW, minor and already disclosed.**
   - Jolpica qualifying is not the post-penalty grid.
   - `exp_pos` and `p_dnf` are not blended.
   - With only 16 races the pre-quali edge over championship order is within noise.
