## Verification

**Contract (api.ts vs pydantic): matches.**
- `Stint { compound: "SOFT"|"MEDIUM"|"HARD"; laps: number; start_age?: number }` vs `StintIn { compound: Literal[...]; laps: int gt=0; start_age: int ge=1 default=1 }`. Names, optionality (omittable, default 1) and units (tyre age in laps, 1 = new set, used N laps = N+1) agree. Pre-existing `SimulateRequest`/`StrategyResult` types are unchanged and still match (`seed?: number` vs `Optional[int]`, response fields identical).
- Not enforced in TS (cannot be): integer, >= 1. The UI enforces both in `getValidationError`.

**start_age logic (read from code, payload traced):**
- Payload: `...(st.startAge !== 1 ? { start_age: st.startAge } : {})`, so new sets send no key at all. Matches the "sent only when != 1" claim.
- Field cleared: `Number("") || 0` gives 0, state is 0, the input stays visible showing "0", validation shows "invalid starting tyre age", Run is disabled, `handleRun` also early-returns on `validationError`. Nothing is sent.
- Typing 2.5: state 2.5, `Number.isInteger` false, Run disabled with the message. Nothing sent. (Backend independently returns 422 `int_from_float` for 2.5, checked.)
- "abc"/NaN: `Number(x) || 0` maps NaN to 0, same path as cleared. Negative: fails `< 1`, blocked. Infinity (e.g. "1e999"): `isInteger` false, blocked.
- Unticking "used set": calls `updateStint(..., "startAge", "1")`, so state is 1 and the key is omitted from the payload. Re-ticking sets 2.
- Add/remove: stint state is keyed by stable `id` and `startAge` lives in the stint row, so removing a stint or strategy cannot shift another stint's value. New stints/strategies are created with `startAge: 1`. There is no reorder feature in the UI, so reordering is not applicable.
- `updateStint` change (`field === "compound" ? value : Number(value) || 0`) keeps the previous laps behaviour (`Number(value) || 0`).

**display-name fix:** diff is a pure rename (`const PitStopDot = ...; return PitStopDot;`). The function body is untouched, so chart behaviour is unchanged. Still called once per render per series at `page.tsx:533`, as before (a new component type each render; pre-existing, not introduced here).

| F-1 | Medium (UX bug) | `frontend/app/page.tsx` ~lines 402-428 (`checked={stint.startAge !== 1}` and `{stint.startAge !== 1 && <Input .../>}`) | The "used set" checkbox and the age input's visibility are both derived from `startAge !== 1`. Typing "1" as the first digit of a multi-digit age (10-19, e.g. select the field and type "15"; or clearing the field and then typing "1") sets `startAge = 1`, which unticks the box and unmounts the input mid-typing, discarding the entry. Ages 10-19 cannot be typed digit by digit; workarounds are the spinner arrows, pasting, or typing the "1" last. Decrementing with the spinner to 1 also collapses the row (arguably intended).
